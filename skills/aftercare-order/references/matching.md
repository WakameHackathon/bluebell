# 匹配与容易回答的澄清

## 当前页面优先

先使用宿主已解析的 PlatformView、获准原始观察和证据到 item_ref/order_ref 的注册映射。PlatformView v1 的 state_facts 是文字事实，不保证其中存在可机器验证的商品映射。没有映射就 needs_observation/missing_input，不从标题、DOM 序号、真实订单号或坐标合成引用。

候选 display_label 用已观察到的名称、款式、店铺或购买时间等最少区分信息。页面未显示的字段省略，不补金额、日期和数量。区分“页面显示蓝色”“用户记得白色”“可能记错颜色”；推测不改写事实。单纯同名不能证明是同一商品项。历史售后记录只有经宿主可靠映射到订单商品项才可成为候选。

有冲突先问能区分的线索或要新观察；不自动相信某一来源。例：“你记得是白色，这条记录显示蓝色。是这一件，还是要找别的？”若冲突涉及商品映射真实性，即使用户选中也先核查。

## 查找路径与停止

只在授权范围内使用用户线索：商品词、款式、时间段、店铺、数量等。不索取完整订单号、地址或手机号。先提出一个有当前证据支持的查找步骤，如查看已打开列表的下一页或核对详情；无已知入口时先要观察，不假设固定菜单。Step.required_evidence 仅使用宿主登记的实际证据 ID，缺少证据用空数组并说明所需观察，不创建未来证据 ID。

每轮写明已查范围、当前过滤条件、是否仅局部可见、是否还有未展示候选以及下一步停止条件。默认一次建议一个最小步骤，由宿主预算限制后续查找；这不是固定总查找次数。找到候选需用户确认；预算耗尽、权限不足、用户暂停、缺少新依据或重复查找无进展时停止并交还主 Agent。没有候选只能说“在已检查范围内未找到”，不可声称订单不存在或已查完全部订单。

中央 v1 无结构化查找范围、截断或完成标记。user_message/issue 可说明给人看，但不能作为自动遍历或终止依据；宿主未另行实现可信范围追踪时禁止自动穷举或自动宣布搜索完成。待实施修订见工程契约提案，不能给 v1 追加字段。

## 候选表达

- 两种款式：“是白色杯子，还是蓝色杯子？也可以选都不是／不确定。”
- 两次购买：“是较早买的这一件，还是最近这次？”时间确实可见才使用“上周”等描述。
- 一单多件：分别展示商品项及可见款式，不能只确认整张订单。
- 只有一个候选：“是要处理这件蓝色杯子吗？”仍须有效用户选择事件。
- “前几天那个杯子”：已有列表就比较候选；没有列表先建议显示相应订单范围，少问已能从页面得到的信息。
- “都不是”：不选任何一件，换线索或建议查看其他获准范围；“不知道”：改问店铺、款式等另一线索，允许暂停。
- 语音名称/颜色/数量不清：给简短文字选项或复述关键差异，不猜同音词，不循环让用户重说。
- “两个都退”：先选本次一件，不自动拆分或批量推进。

宿主有获准缩略图可建议候选卡片；不自行抓取或外发图片。只展示少量时说清还有其他候选，不能把截断后的候选集合当全量。候选选项 value 可使用实际 item_ref；none/unsure 只表示回答选项，永远不成为 selected_item_ref。
