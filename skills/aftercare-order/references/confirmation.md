# 确认、复用与失效

三件事分开：意图确认（理解诉求）、商品选择（本次哪一件）、执行授权（提交等具体动作）。任何一种不替代其他种。

## 可引用选择的条件

宿主解析 UserDecision，核验 decision_kind=select_item、真实用户输入事件、当前 task_id、selected_value_ref 对应实际候选 item_ref、subject_ref 对应当时呈现的候选集合及其版本；选择含义明确且没有未解决的语音识别问题。selection_receipt_ref 只使用宿主明确登记的凭证 ID；不可猜它就是 artifact_id、decision_id 或 user_event_ref。宿主如约定使用 decision_id，须提供该映射和解析记录。

宿主还须证明该选择在当前账户、平台、商品映射、候选版本及任务修订中仍适用。选择事件引起任务版本增加是正常的；不机械比较 decision.based_on_task_revision == 当前 revision，应核验中间事件允许的迁移。artifact revision、task revision、page revision 互不等同。

单独“是”必须关联已呈现的问题与实际 item_ref；页面文字、商家声明、模型输出、ASR 原文或 confirm_fact 不创建选择。只有合法 Ref 而没有来源/绑定正文时，不认可确认。已经明确回答但宿主绑定缺失时 blocked/contract_error，说明需恢复选择记录，不反复要求用户确认。

在当前 v1 未解决意图确认和商品绑定运行时缺口时，可保留候选，但不填选择字段，不交给申请流程。若收到未来迁移宿主的数据，不自行启用新协议，应由主 Agent 选择已协商消费者版本。

## 变化处理

| 变化 | 身份选择 | 控件与下一步 |
|---|---|---|
| 仅布局变化，宿主验证同账户同 item/order 映射 | 不自动废弃有效身份确认；无需再问用户 | 旧控件全部失效，needs_observation/stale_observation，取得新 PlatformView |
| 补充描述但目标/意图未变 | 可复用，需宿主验证无语义变化 | 根据新观察继续 |
| 账户切换、候选集合改变或映射改变 | 重新核对，不沿用无法证明适用的旧选择 | 未核实两个选择字段 null；请求新观察或选择 |
| “不是这个，是另一个” | 旧选择失效；只有新有效选择事件才确认新项 | 报告旧状态失效依据，由宿主比较版本更新 |
| 改为保留商品或改变售后目标 | 报告主 Agent 回 intake，不能只换商品引用 | 停止旧路线，不授权撤销申请 |
| 暂停/过期结果/同调用重传 | 不恢复旧任务、不生成新凭证 | 宿主暂停门禁、丢弃迟到结果、返回已存结果 |

v1 的失效依据只能放 Issue.message/evidence_refs 供主 Agent 审核，不能伪装成已执行的状态更新或可机器解析的动作命令。不能把“页面布局变了”一概解释为用户需要再次确认身份；也不能因为身份有效而使用旧定位。
