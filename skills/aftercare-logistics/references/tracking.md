# 运单、实际寄件与物流

运单记录需区分 direction=return/original/unknown，来源 user_reported/ocr/platform，识别状态与匹配核实状态。长度/字符格式正确仅说明格式；不能证明真实、所属商品或本次退货。语音数字/字母或 OCR 不清时请用户对照指定材料核对，不猜补字符。OCR/文件读取仅由获准工具处理指定材料，不扫描目录。

核对任务、商品项、售后实例、包裹、承运服务与平台记录的关联。发现已有运单先对照，不覆盖；存在多个包裹而当前关联不明确时停止填写，不扩成多件批量流程。用户说已寄出即停止再安排取件，但保留 user_reported 来源，先核对本次运单；与平台待寄件冲突不能抹去任一方。仅运单生成不足以判断已交寄。

分别解释：已预约→等待取件；已生成运单→是否交寄未证实；已揽收→承运方已接收，商家未必收到；已签收→投递签收，不证明商家认可商品；商家收货→不证明退款完成。退款完成只由相应最新 OutcomeReport/平台退款证据核对，不从签收推断。本 Skill 不替 remedy 改方案。

自行寄件时只整理平台要求和后续运单核对准备，不代办独立快递平台。包装、配件、标签、寄回数量、期限只依据当前适用指引；无依据不要要求丢包装、拆商品/封条、寄无关配件或重现危险故障。特殊寄递要求请平台或快递官方确认，不保证可寄。给用户当前一两件具体待办；技术查证留给主 Agent。

当前 v1 tracking_ref 也无可验证类型/来源协议。仅在宿主已登记、已匹配本次退货且来源可追溯时引用；若无绑定机制，保持 null 并请求核对。不会生成运单号或以识别文本冒充引用。
