# 异常、状态与交接

| 情况 | 分析与建议 |
|---|---|
| 预约已发出/可能发出、缺回执、超时 | needs_observation/ambiguous_result；verify核对预约记录；retryable=false，禁止重复预约 |
| 一次没有查到记录 | 保留未知，不能写失败；无可靠查证路径则官方客服交接 |
| 已预约/已生成运单 | 不再预约；解释实际已确认阶段，必要时verify |
| 用户说已寄出或平台已揽收 | 不再安排同一包裹；核对来源和运单 |
| 长期无更新/取件未发生/异常 | 描述有证据的最后状态和时间，请主Agent获取当前平台信息；不猜丢件原因或保证到达时间 |
| 期限临近/已过或特殊限制 | 依据明确期限及来源解释；未知时请求证据；无可靠路径建议handoff，不编宽限期 |
| 取消或改约 | 本包首版只解释、核对现状；不支持正式动作准备，blocked/unsupported。今后支持仍要具体确认与执行后verify，不能包装为navigate |
| 页面变化 | needs_observation/stale_observation，由主Agent取新观察，必要时recover；不用旧控件/时间 |
| 新会话、模式变化、暂停后继续 | 旧提案不得执行；新观察→verify→resume→当前物流分析，不恢复历史授权 |
| 支付/登录/验证 | blocked，用户本人完成；不索取凭据、不绕过 |

用户无法补充时先用已有可靠信息；问“包裹现在还在您手里吗”比要求物流术语更具体。仍不清楚时提供当前平台记录核对或官方客服帮助，不循环同一问题。没有当前可靠入口不能编按钮名称。

主 Agent 决定交接，本 Skill 不调用下游：选择缺失→具体问题；条件及契约齐备后→interact；任何预约/运单提交/取消之后→verify；页面失效→recover；跨会话→verify/resume；无路径→handoff。后两类计划消费者存在不等于已部署服务，handoff未实现时保留待办。不给用户提供未经平台确认的站外地址或独立快递代办。
