# 历史确认、模式与权限

historical_consent_reusable 永远 false，含已消费确认、旧会话未执行确认和旧提案。历史事实/目标/偏好可用作上下文，但不能成为重新执行许可。

商品选择：select_item 绑定任务、候选集合、item/order/账户及呈现版本。方案：choose_option 绑定当前商品、方案集合与金额/费用/期限等语义摘要。材料：review_material 绑定文件字节、派生链、要求、说明和呈现记录。对象与内容未变、宿主证明迁移仍有效时无需重问。现有上游 v1 强绑定不完整，不能用 Skill 自报 confirmed 补齐。

访问范围与执行确认分开：现有页面/文件/模型接收方权限可能持续有效，由宿主复核，不要求每次重新授权；撤权、内容/接收方/用途变化则重新检查。用户当前新的有效选择可替代旧选择，不得因历史更新时间较晚拒绝它。新的关键动作确认只能由执行层针对新提案生成并消费，ResumePlan 不携带令牌。

查看进度：可以比较、解释和列缺失证据，但本包 next_steps=[] 防止被误消费为续办。用户明确继续仍须先核当前证据。self 只说明；guided 由用户操作；auto 仅向主 Agent 建议。暂停时 blocked/user_paused 且无步骤；允许回顾已知事实，但不解除暂停、变更模式、重开旧租约。

恢复边界应由宿主递增 session/lease epoch，撤销旧未执行提案能力；已发出动作保留台账，旧确认不可再次消费。暂停/切任务/账户/页面/文件/方案/接收方变化也使相关提案失效。只有身份/语义变化才使对应选择失效，不能把每次 revision 增加机械当作用户重新选择的理由。
