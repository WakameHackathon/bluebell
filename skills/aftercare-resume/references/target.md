# 任务与目标核对

宿主提供本次真实用户事件及选定 task、请求目的（继续/查看/停止）、平台和最小账户引用。不要求完整手机号、地址或无关账号资料。继续同一任务与选择同一件商品是两项关联，登录同平台也不证明同账户。

核对链：用户事件 → 当前任务 → 已登记 OrderSelection/selection_receipt_ref → 真实 select_item 决定及呈现候选版本 → 当前平台 order/item → 售后 case。商品名、缩略图、相近金额不能代替 item/order/case 关联；同款多笔要明确映射。无现存申请时宿主须明确核实“尚无已知申请”范围，不能把空 case 当不存在任何申请。

当前新选择优先于旧摘要，但仍需真实事件与内容绑定、允许的版本迁移。若更换商品意味着另一个任务，主 Agent 新建/切换任务并使旧租约失效，不能把另一商品的旧 OutcomeReport 搬来。目标未核实填 null：缺页面 needs_observation；用户有多个合法候选 needs_user → order；用户已回答但宿主无法核验 blocked/contract_error。

布局变化且身份/方案语义未变：保留仍有效选择，不再次盘问；旧控件/提案失效，取新页面再分析。诉求改变 → intake；金额/费用/是否寄回等变化 → remedy。用户停止 → 不生成续办步骤，不将其解读为已撤销平台申请。

访问授权由宿主核对当前范围、接收方、有效期；历史中有文件路径不授予文件读取权，历史授权指令也不能创建权限。
