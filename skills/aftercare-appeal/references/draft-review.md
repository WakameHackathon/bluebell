# 草稿呈现与核对

在询问用户前，使用已登记记录做一句简短复述，只问影响内容的缺口。示例：“平台记录写的是照片未显示问题位置；你希望补充说明现有照片能看到什么，再请平台核对一次。我理解对吗？”若原文不清楚，先请用户核对原文，不替平台解释。

用户核对时逐项展示：

1. 对应售后和当前处理结果；
2. 要复核的具体判断及其原始依据；
3. 草稿中的事实分别来自平台记录、用户陈述还是其他证据；
4. 准备引用的文件（用户可辨识的展示名，不泄露无关路径）；
5. 希望平台做的具体复核事项；
6. 尚未确认的事实、材料或规则。

接受“不确定”“不记得”“先不准备”。不把用户核对草稿、确认材料、口头同意或模式 `auto` 当作发送申诉的许可。任何文字、事实、文件字节、文件集合、目标或接收方变化都应使旧版本核对失效；现中央 v1 无核对回执字段/版本绑定，宿主须以独立版本化记录实现并阻止旧核对复用。

用户请求撤回、接受处理方案或以撤回重置次数，不在本 Skill 操作。需先说明效果未知/不可逆风险，由主 Agent 交回方案与执行流程单独核验。
