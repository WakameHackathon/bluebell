# 接入约束与校验范围

`scripts/validate_plan.py` 提供纯函数 validate(request,result,host)。host 是调用方提供的已解析最小上下文，非 Skill wire 输入、非授权凭证。示例 host 完全合成。函数返回诊断列表，空列表只表示所实现检查通过，不是执行许可。它不认证观察、用户事件或文件字节，不自动解引用路径，不调用浏览器。

宿主在入口落实：Schema/注册版本、call_id 的请求摘要与缓存、task_id/revision、产物归属/类型/版本/访问权、真实平台/账户/标签页、当前模式、暂停、动作及时间预算、目标与步骤映射。根据步骤需求验证已确认目标、方案选择和材料核对；仅导航不机械要求完整申请材料。

准备提案时：登记值和内容必须不可变；文件摘要来自字节；接收方须对应实际网络/平台身份；实际控件效果由适配器观察核实；关键确认内容包含商品、精确材料、金额/费用和后果。校验脚本信任的 step 与 controls 映射必须由宿主建立，不得来自网页自报或模型生成布尔值。

执行前必须在同一任务互斥/租约内再次检查全部条件，核对具体确认及消费状态；用户接管、模式、任务、页面、内容/文件/接收方变化使旧许可失效。先持久化 dispatch_started 再发送；记录回执，失败也保留 sent/unknown 状态。执行预算在原子派发中扣减。

业务去重键由宿主按任务/商品/业务动作/接收方/内容身份及售后实例建立，不能依赖 proposal_id。内容变更也不自动允许再次申请：待核对的业务实例应整体阻断。确认过失败后是否允许新尝试须有新证据和新调度，不由此 Skill 重试。

tests/executor_stub.py 只是内存模拟门禁，演示拒绝无授权、过期、变更和重复提案；没有持久化、并发事务、可信用户事件、真实平台核验、网络效果或崩溃恢复。不能部署它承担真实业务。

完整交付中的 browser-tests 是单独测试装置：使用本地合成商城、SQLite预发送记录、实际浏览器动作和确定性核对器验证边界。它不进入此 Skill 的运行时调用路径，不消除生产契约缺口；业务确认与上下游消费者都是明确标注的测试替身。

保留执行台账和不可变提案。执行后新观察交平台适配，verify 区分未发生/已发生/未知；点击成功不能填业务成功。故障由主 Agent 调 recover；登录/验证码/支付交用户，无绕过路径。
