# 核对、版本与失效

展示具体拟用文件，指出原件或派生、来源、压缩/方向及元数据变化；核对是否看得清问题与上下文，再核对短事实说明。不要求用户理解摘要值或技术术语。

核对事件必须由宿主从真实用户交互登记，不接受模型生成 review_receipt_ref。其含义是认可一版材料，不是授权上传、发送或申请。中央 v1 只能引用一个字符串，缺完整绑定；当前保持 null，正式交接关闭。

拟议绑定使用：task/item/plan 与关键条款版本、材料要求版本、明确拟用文件集及每个内容摘要、派生来源/变换参数、说明事实内容摘要、呈现记录、UserDecision 与用户事件。宿主核验真实性与有效性，模型输出不是授权。

文件增加、替换、重新处理、原件字节变化、事实说明变化、商品/方案/要求变化均要重核；若影响本次呈现则旧核对失效，重新展示变化部分。仅展示标签改名不改内容身份，不自动失效；布局变化刷新观察，重新确认要求语义版本仍一致后可保留内容核对。不能只比文件名，也不能把 task revision 的任何增加一律当事实变化。

对用户已明确核对、只是宿主尚不能登记的情况，不反复索取“对”；返回 blocked/contract_error，并保留草稿。用户纠正事实后更新草稿，交宿主废弃旧绑定。文件归属、授权撤销、源内容变化即使用户曾认可也不能沿用旧文件能力。
