# 有限恢复、接管与模式

每次指出新依据、与上次路径/条件的差异、要验证的观察/业务结果，以及停止或交接条件。剩余 actions、recovery_attempts、deadline_at 由宿主预算控制；Skill不自增、不清零、不因新call/新proposal重置。首次缺观察可提出一次观察请求；同路径同条件重复失败或没有新依据后停止自主恢复。

停止条件：用户暂停/接管；预算耗尽或截止；同条件无进展；必须由用户提供的事实、选择、登录、验证码或访问许可；平台明确不支持；重复或未经授权效果；订单/接收方不明。stop 的 next_steps=[]。停止只表示当前恢复停止，保留已完成步骤、未知外部效果和待办，不宣布整笔任务结束或拒绝。

self：可理解的恢复说明，不建议自动执行。guided：用户自己操作，允许主 Agent 交陪同层解释和高亮。auto：可提出一条路径，由 interact 单步提案及执行层核对。RecoveryPlan 在三模式都不是执行指令。

暂停采用已开始最小步骤结束后停；不得再开始查页面、刷新、关闭弹窗等新恢复动作。继续时重新观察并重新规划，旧计划失效。模式变化也要使旧计划失效。接管后先理解用户造成的新状态，不自动恢复旧字段；改商品/诉求分别交 order/intake，改方案交 remedy。

ask_user 必须问本人能回答的具体缺口，例如“你刚才是否主动改选了这件商品？”而非要求用户判断网络请求是否发送。工程机制缺失不能通过重复让用户点同意解决。handoff 包含已核实进度、未核实的原动作及记录对象、尝试历史、当前限制、官方渠道待核实事项；准备草稿不代表已发送。
