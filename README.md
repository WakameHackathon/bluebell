# Bluebell 项目说明

> 网页操作助手

## 一 项目概述

Bluebell 是一款以浏览器插件为载体的网页操作辅助助手。用户在网页上遇到入口难找、说明难懂、材料准备不清楚等问题时，可以点击悬浮球，在侧边栏直接说出自己的目标和困难。Bluebell 结合用户主动提供的页面文字，通过对话确认需求，帮助用户看懂要求、整理材料、明确下一步操作。

我们希望把帮助放在用户真正需要它的地方：正在浏览、正在填写、正在犹豫下一步怎么做的网页旁边。产品围绕具体任务组织交流，让用户能够一边查看页面，一边获得解释，并始终掌握信息分享和操作决定权。

## 二 需求背景与应用场景

网站把越来越多的业务搬到线上，用户仍需要逐个适应不同的页面布局、业务术语和操作顺序。同一件事换一个网站，入口、材料格式和填写要求就可能发生变化。反复查说明、切换页面、补齐材料，构成了网上办事中常见的时间成本。

### 秋招求职

求职者面对不同企业的招聘网站，需要反复寻找申请入口、阅读岗位要求、确认简历和附件格式。Bluebell 可以结合当前页面解释投递要求，帮助用户梳理填写顺序和待准备材料，减少在多个网站之间重新摸索的负担。

### 账号管理与日常办事

注册账号、修改资料、了解账号设置，以及办理线上政务业务时，用户常被陌生术语和分散说明打断。Bluebell 可以围绕用户当前目标解释页面文字，整理操作前提和步骤，让用户更容易判断接下来要做什么。

### 协助长辈预约挂号

帮长辈预约挂号时，需要读懂预约规则、就诊人信息要求和页面提示。Bluebell 聚焦流程解释与材料准备，帮助代办者逐项核对。涉及诊疗判断的事项应以专业医务人员意见为准。

## 三 产品核心亮点

- 贴近页面的帮助。悬浮球与侧边栏让用户在原有浏览过程中发起求助，减少在网页、搜索结果和聊天窗口之间来回切换。对话可以直接围绕当前页面展开，帮助更具体，也更容易核对。
- 由用户把握信息分享。读取页面需要用户授权并主动触发；读取的是当前页面的可见文字。用户可以先检查、修改，再选择是否发送给模型。逐轮选择让信息分享成为使用过程中的明确动作。
- 围绕任务持续交流。Bluebell 通过追问补齐必要信息，帮助用户整理页面要求和下一步操作。任务记录保存在本机，方便稍后接着聊，减少重复说明背景的麻烦。

## 四 交互流程与架构设计

产品的核心流程为：打开侧边栏并描述任务，主动授权读取页面文字，检查与编辑待分享内容，选择本轮是否发送给模型，查看解释并继续提问。用户根据页面实际情况作出操作决定，任务记录留存在本机供后续继续。

以下为依据产品定位整理的建议技术方案，用于说明模块分工和实现思路；具体框架、接口及代码实现需与项目仓库核对后确定。

### 浏览器交互层

由悬浮球、侧边栏、内容预览编辑区和任务记录入口组成。侧边栏承载需求描述、澄清问题和操作建议；预览编辑区呈现本轮准备交给模型的内容，使授权、读取和发送三个动作有清晰的界面反馈。

### 页面文字处理层

在用户授权并主动点击后获取当前网页可见文字，整理标题、正文、表单标签与提示信息。建议对重复导航和无关文本进行清理，同时保留材料格式、时间限制、必填项等影响办理结果的信息。页面更新后，应由用户再次触发读取，避免旧内容被误当作当前状态。

### 任务与对话层

围绕用户目标组织页面片段、已确认条件和待澄清问题，再交给模型分析。建议将输出组织为页面要求、所需材料和下一步操作，并在需要时指出对应的页面依据。页面没有提供的信息应明确留待确认，帮助用户区分网页原文与助手的推断。

### 模型接入层

建议将模型调用与插件交互分开，通过统一接口传入用户确认的本轮内容。接入层处理请求状态、超时、取消与错误提示，避免失败时重复发送。后续可按部署条件连接本地推理服务或经配置的模型服务，具体方式以实际实现为准。

### 本机任务记录层

按任务保存对话记录与继续交流所需的上下文。建议提供清晰的查看和删除入口，并控制持久保存的内容范围。恢复历史任务时，应提示用户核对当前页面是否已变化；本机保存与模型处理是两个独立环节，界面应分别说明。

## 五 Agent Skills 设计方案

Bluebell 将页面解读、材料整理、步骤梳理和需求澄清划分为职责清晰的 Agent Skills，并通过 Markdown 文件描述各项能力的适用场景、输入内容、执行步骤、输出格式和限制条件。各项能力围绕同一任务配合工作，帮助用户从看懂页面逐步走到明确下一步操作。

页面解读 Skill 负责解释业务规则、表单字段和提示信息；材料整理 Skill 提取所需材料的名称、格式与准备条件；步骤梳理 Skill 结合页面要求和用户进度，整理当前可执行的操作；需求澄清 Skill 识别影响判断的缺失信息，通过追问确认用户的具体情况。

各项 Skill 遵循统一的授权与内容确认规则，仅围绕用户确认分享的内容开展分析。网页文字作为待分析的材料，不具有修改系统权限或触发额外操作的权限。遇到含糊或依据不足的信息时，助手会明确指出需要确认的内容，向用户询问或请求补充页面说明。

这种分工让各项能力可以独立验证和持续优化。团队能够针对具体问题改进提示词和输出格式，将不同场景中积累的经验复用到后续任务中，提升回答的准确性与实用性。

## 六 本地部署与优化方案

Bluebell 的本地部署方案以浏览器插件为交互入口，以本地算力设备承载模型推理服务。用户确认本轮发送内容后，插件通过受控接口提交分析所需的信息，推理结果返回侧边栏，供用户结合原网页查看和核对。任务记录由客户端在本机管理，支持后续继续交流。

部署流程围绕设备环境配置、模型服务启动、接口连接和插件联调展开。部署文档记录模型版本、推理框架、运行依赖、启动命令与连接配置，便于安装和复现。功能验收覆盖页面读取、内容编辑、逐轮发送、任务恢复及请求失败后的提示，确保从页面获取到结果呈现的流程完整、清晰。

### 输入内容优化

页面内容处理以用户当前任务为中心，保留相关说明，清理重复导航和无关段落。截止时间、材料规格、必填项及办理条件等关键信息作为重点保留对象，避免内容精简影响判断。对于较长的对话，采用用户可核对的任务摘要整理上下文，同时保留关键规则的原文依据。

### 响应体验优化

回答优先呈现用户当前最需要的信息，让页面要求和下一步操作更容易找到。响应过程通过清晰的状态提示反馈处理进度。模型配置围绕设备资源和交互需求展开，结合模型规模与量化方案，综合评估响应速度、资源占用和中文页面理解质量。

### 质量评估与持续改进

质量评估围绕招聘投递、账号管理、预约和政务流程等代表性场景展开，重点检查规则提取是否准确、材料是否遗漏、步骤是否可执行，以及内容发送是否经过用户确认。同时记录响应时间与资源占用，用可重复的测试结果定位问题，为模型配置、页面处理和 Skills 优化提供依据。

## 七 项目价值与发展方向

Bluebell 将网页说明转化为用户可以理解和核对的办事指引。对于求职者，它有助于减少跨网站投递时反复熟悉流程的负担；对于协助家人办事的人，它提供随页面展开的解释；对于不熟悉某类线上业务的用户，它让陌生的规则更容易理解。

项目具有跨场景复用的空间：不同网站的业务内容各异，但读懂要求、准备材料、明确步骤是共同需求。以页面内容和任务对话为基础，Bluebell 可以持续积累场景化 Skills。后续重点是提升复杂页面理解、任务恢复和提示准确性，使每次帮助都更贴近用户当下的操作。
